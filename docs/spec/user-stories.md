# Open-Lens 用户故事 Spec

> 依据:Microsoft Lens(退役,功能基准)、[OSS-DocumentScanner](https://github.com/ossappscollective/OSS-DocumentScanner)(检测管线与交互参考)、本仓库 ADR 0001-0007、CONTEXT.md 术语表、spike 验证结论。
>
> 优先级:P0=MVP / P1=v1.1 / P2=后续 / ✂=不做。**范围已于 2026-08-16 与用户对齐定稿**,决定记录见第 6 节。

## 1. 产品定位

自托管文档扫描系统,替代退役的 Microsoft Lens:

- **手机端(iOS Safari PWA)**:相机采集、边缘检测、透视校正、增强、Outfit 组装,全部本地 OpenCV.js 完成,离线可用。
- **云服务器(aliyun)**:唯一数据真相。归档 Original + Outfit,SQLite 存元数据,向 AI agent 开放 MCP 接口。

单用户自用,不做用户系统。区别于上游 OSS-DocumentScanner 的核心点:**本项目不是独立 app,而是"采集端 + 自有服务器归档 + agent 可编程访问"的三件套**。

**头号场景**:课堂连拍投影/板书,课后 agent 直接取用整理。所有 P0 取舍以它为裁判。

## 2. 角色

| 角色 | 说明 |
|---|---|
| **扫描者** | 用户本人。手机上扫描、编辑、组织、导出。 |
| **Agent** | 用户的 AI 助手,经 MCP 读取和组织扫描件;需要的 Outfit 自行组装。 |
| **服务器** | 归档、API、MCP。无 UI(或仅最小状态页)。 |

## 3. 用户故事

### Epic A — 采集(Capture)

**US-A1 实时取景边缘高亮** · P0(可降级)· [OSS-DS][ADR-001][spike✓]
作为扫描者,打开相机后我想在取景画面上实时看到检测到的文档边框,以便对准文档。
AC: 视频流上叠加四边形高亮;帧率 ≥5fps 时维持;spike 已验证降级路径。工期吃紧时第一个献祭,降级路径 = US-B3(拍后检测 + 手动拉角,已验证)。

**US-A2 手动快门** · P0 · [Lens][OSS-DS]
作为扫描者,我想按快门键拍下一页,以便我控制成像时机。
AC: 点击快门 → 冻结帧 → 进入拍后检测流程(US-B1)。

**US-A3 连续多页采集** · P0 · [Lens][OSS-DS]
作为扫描者,扫多页文档时我想连续拍下每一页、拍完统一确认,以便一次产出多页文档。
AC: 拍一页 → 检测/微调 → 确认 → 自动回到取景拍下一页;「完成」结束会话生成文档;页序 = 拍摄顺序。

**US-A4 相册导入** · P0 · [Lens][spike✓]
作为扫描者,我想从相册多选照片导入并批量走检测/校正/增强,以便用已拍好的照片补扫描。
AC: 多选 → 逐张检测(失败的走手动角点)→ 并入当前文档。

**US-A5 手电筒(torch)** · P1 · [Lens][OSS-DS]
作为扫描者,在暗处我想开启常亮补光,以便文档边缘可检测。
AC: 取景界面提供开关;通过 track.applyConstraints 控制。

**US-A6 自动快门(检测稳定即拍)** · ✂建议不做 · [OSS-DS]
OSS-DS 支持"边框稳定 + 无运动模糊自动拍摄"。
建议不做:需要稳定性/模糊判定启发式,收益主要在连续批量场景,而本项目 US-A3 已提供快速连拍;省下复杂度。

**US-A7 分辨率/对焦点控制** · ✂建议不做 · [OSS-DS]
iOS Safari 不暴露 Android 式分辨率选择;tap-to-focus 由系统相机手势承担(PWA 内不可靠)。不做。

### Epic B — 检测与校正(Edge Detection & Correction)

**US-B1 拍后检测 + 角点微调** · P0 · [OSS-DS][ADR-001][spike✓]
作为扫描者,拍下一页后我想看到自动检测的边框并可拖动四角微调,以便自动检测不准时救回。
AC: 冻结帧上显示检测四边形;四角可拖;实时预览透视校正结果;spike 已实现。

**US-B2 透视校正生成 Scan** · P0 · [OSS-DS][Lens]
作为扫描者,确认边框后我想得到一张边是直的、平行边平行的成品图,以便文字可读。
AC: 四点透视变换输出 Scan;输出尺寸按文档边长比自适应。

**US-B3 检测失败降级** · P0 · [ADR-001 预批]
作为扫描者,检测不到四边形时我想直接框全图手动拉角点,以便任何照片都能出结果。
AC: 检测失败不报错阻断;给全图默认框进入手动模式。

**US-B4 90° 旋转** · P1 · [Lens][OSS-DS]
作为扫描者,我想把页旋转 90°/180°/270°,以便竖拍横文档不出歪图。
AC: 页编辑器提供旋转;旋转持久化到页元数据。

**US-B5 从 Original 重切(re-crop)** · P1 · [ADR-002]
作为扫描者,我想对已归档的页重新选区,以便事后发现切歪了能修。
AC: 从服务端拉 Original → 重跑检测/手动角点 → 生成新 Scan(Original 不变)。

### Epic C — 增强(Enhancement)

> **桌面批量增强后置约束**:桌面批量增量当前只做透视校正。新增增强前必须先补齐“参数化、可复用处理管线、Original/成品对比”三件套；完整范围以 [增量 spec #2](https://github.com/ren2019/open-lens/issues/2) 为准，不在这里复制。

**US-C1 增强选单** · P0 · [Lens][OSS-DS]
作为扫描者,我想在几个预设增强里切换:原图 / 灰度 / 黑白 / 彩色增强,以便不同内容选合适效果。
AC: 四档预设;黑白为二值化(文字最优),灰度保调性(图表),彩色增强做白平衡+对比度;单页即时预览。落地前用 spike/photos-batch/ 真实照片把四档预设人眼过一遍(每档在其设计场景可用),一次性排雷;参数不冻结,后续可随时调整。

**US-C2 全文档统一增强** · P1 · [Lens][OSS-DS]
作为扫描者,我想一键把整个文档所有页切到同一增强,以便成品观感一致。
AC: 文档级"应用到所有页"操作。

**US-C3 亮度/对比度滑杆** · P2 · [Lens][OSS-DS]
预设之外的手动微调。建议后置:四档预设已覆盖大部分场景;滑杆引入参数持久化复杂度。

**US-C4 文档增强档(阴影去除)** · P2 · [OSS-DS]
OSS-DS 的 "Document Enhancement"(阴影去除、 uneven lighting 校正)。板书投影场景收益高但算法成本高,建议 P2 观望——先用彩色增强档顶。

### Epic D — 文档与页组织(Organization)

**US-D1 页序调整** · P0 · [Lens][OSS-DS]
作为扫描者,扫完后我想拖动缩略图调整页序或删页,以便修正拍摄顺序错误。
AC: 文档视图内重排 + 删除;变更同步到服务端。

**US-D2 文档重命名** · P1 · [Lens][OSS-DS]
作为扫描者,我想给文档改名(默认名 = 日期),以便日后能找到。
AC: 默认 `YYYY-MM-DD HH:mm`;可改;改名同步服务端。

**US-D3 标签** · P0 · [ADR-002][2026-08-16 提前进 MVP]
作为扫描者,我想给文档打标签(如"板书/讲义/发票"),以便按主题检索。
AC: **平面多标签**(一维多选,标签集随打随建,不做层级);列表按标签筛选;标签存 SQLite;**打标签入口在两端**——手机端(扫描会话结束/文档详情)与 MCP I3 共用同一 service 层。

**US-D4 历史列表** · P0 · [ADR-002]
作为扫描者,我想在手机上浏览服务端归档的全部文档(缩略图 + 名称 + 日期),以便回看和重新导出。
AC: 列表从服务端拉取,本地无档;下拉刷新;离线时显示缓存 + 提示。

**US-D5 搜索** · P1 · [2026-08-16]
作为扫描者,我想按名称/标签搜索文档。OCR 就绪后扩展到全文(依赖 Epic K)。
AC: 名称 + 标签子串匹配;OCR 字段就绪后并入。

**US-D7 远程文档详情与再导出** · P0 · [2026-08-19 补,UI 原型收口时发现]
作为扫描者,我想在历史列表点开任意已归档文档,浏览各页并重新导出(单图/PDF/长图),以便不回溯拍摄会话也能取用旧扫描。
AC: 详情页展示页缩略 + 名称 + 标签 + 日期;导出直接取服务端 Scan/Outfit,不要求本地有档;入口为 US-D4 列表项点击。D4 的 AC 含"重新导出",无详情页则该 AC 实际不成立——本故事是补漏,不是增量。

**US-D6 删除与回收站** · ✂建议不做回收站 · [OSS-DS]
删除文档(连文件)直接做;回收站不做——单用户自用,server 是唯一真相,误删的恢复成本高于回收站的常驻复杂度。

**US-D8 桌面批量重切** · P1 · [2026-08-20]
作为扫描者,我想在桌面浏览器批量回看已归档文档、对不满意的页拉 Original 重切,以便大屏上高效修整历史扫描件。
AC: 复用手机端同一套前端与 OpenCV.js;处理在桌面浏览器完成,服务端零改动。

**US-D9 桌面批量导入与成品墙** · P1 · [#2]
作为扫描者,我想在桌面端批量导入已有课堂照片、复核检测提案并从成品墙二次修正,以便数百张照片不必逐张走手机旅程。
AC: 本条只保留 spec 入口;范围、实现决定、telemetry 回填与 Seam 1 验收的单一真相是 [增量 spec #2](https://github.com/ren2019/open-lens/issues/2),经验与数据纪律见 [批量标注 lessons](../lessons-2026-08-18-batch-labeling.md)。

### Epic E — Outfit 导出

**US-E1 单页图导出(JPEG)** · P0 · [Lens]
作为扫描者,我想把某页 Scan 存成图片文件,以便发给别人或贴进笔记。
AC: 导出/分享单页 JPEG;质量默认值可后续配。

**US-E2 PDF 组装** · P0 · [Lens][OSS-DS]
作为扫描者,我想把文档的多页组装成一个 PDF,以便归档和打印。
AC: 手机端组装(pdf-lib 或等价);页序即组装序;上传 Outfit 归档。

**US-E3 长图拼接** · P0 · [CONTEXT.md]
作为扫描者,扫竖版板书时我想把多页上下拼成一张长图,以便一张图看全整面板书。
AC: 等宽缩放后垂直拼接;可作为 Outfit 类型;上传归档。

**US-E4 导出参数(质量/页边距/纸张)** · P2 · [OSS-DS]
OSS-DS 的 PDF 设置(页 size、边距、JPEG 质量)。自用场景默认参数即可,后置。

**US-E5 打印/批量导出** · ✂建议不做 · [OSS-DS]
系统打印、多文档批量导出。单用户低频,浏览器自带打印 PDF,PWA 批量导出价值低。

### Epic F — 上传与离线队列

**US-F1 归档上传** · P0 · [ADR-001][ADR-002]
作为扫描者,每页确认后我想自动上传 Original + Scan + 文档元数据,无需手动保存。
AC: 会话结束/页确认触发上传;服务端按 `YYYY/MM/` 落盘 + SQLite 记元数据。Original 归档统一长边 2560px(相机 ideal 2560;相册导入超限先降采样再归档)。

**US-F2 断网继续扫 + 后台补传** · P0 · [ADR-001][ADR-002]
作为扫描者,没信号时我想照常扫描,恢复网络后自动补传,以便教室无网也不受阻。
AC: 队列 OPFS 硬持久;PWA 重开或网络恢复时前台自动续传(iOS 无真后台上传);上传失败不丢弃,重试超限转人工单条重试(US-F3);待传计数常显;启动时 navigator.storage.persist() 尽力请求;持久承诺以已安装主屏 PWA 为前提(US-H1 为显式前置),Safari 标签页使用不承诺持久。

**US-F3 上传状态可见** · P1
作为扫描者,我想看到待传数量/进行中状态,以便知道归档是否完成。
AC: 队列计数指示;失败项可单条重试(仅会话内)。

### Epic G — 服务端归档与 API

**US-G1 归档存储** · P0 · [ADR-002]
服务器接收上传:文件按 `YYYY/MM/` 落盘(Original + Outfit),元数据(名称、标签、页序、OCR 占位)入 SQLite。
AC: 幂等接收;文件路径可从元数据推导。

**US-G2 库 API(列表/详情/改组织)** · P0 · [ADR-002]
手机端历史视图与 MCP 共用的 REST 面:列表、详情、重命名、打标签、页组织。
AC: 单 token 鉴权;JSON 返回;MCP 工具复用同一套 service 层。

**US-G3 单 token 鉴权** · P0 · [ADR-004]
前端首次输入 token 存 localStorage,服务端校验环境变量;MCP 共用。
AC: 无 token/错 token → 401;应用层只听 HTTP(HTTPS 由 Caddy 终结)。

**US-G4 部署(renzhhen.me 子域 + Caddy)** · P0 · [ADR-004]
作为用户,我想把服务部署到 aliyun 并通过 HTTPS 子域访问,以便 iOS Safari 相机 API 可用。
AC: Caddy 自动证书;iOS PWA 可安装可开相机。

**US-G5 服务端冷备** · P0(运维)· [2026-08-20]
作为用户,我想服务器数据每日有异地副本,以便单盘故障不丢档案。
AC: NAS pull 模式(NAS 侧 cron rsync 拉取,服务器零凭据);SQLite 先 dump 再拉;保留 30 份快照;验收 = 恢复演练一次(挑一份快照本地恢复出可查询的库,记录进 lessons);磁盘水位 80% 告警,不做自动清理;OSS 为无 NAS 时的备选。

### Epic H — PWA 与加载

**US-H1 PWA 安装** · P0 · [ADR-001][spike✓]
作为扫描者,我想把 Open-Lens 加到主屏并以 standalone 模式运行,以便像原生 app 一样全屏使用。
AC: manifest + 图标;iOS Safari 添加到主屏;standalone 下相机可用(spike 已验证)。

**US-H2 OpenCV.js 加载策略** · P0 · [ADR-006]
作为扫描者,首次打开后我想 WASM 被缓存,以便二次进入不重新下 8-10MB。
AC: service worker 缓存或裁剪构建;加载中有进度提示;离线二次打开可用。

**US-H3 环境自检与能力门** · P0 · [2026-08-20]
作为扫描者,环境不达标时我想被明确告知并能理解出路,而不是用着用着静默丢数据。
AC: 冷启动特性检测(getUserMedia/secure context/WASM/OPFS/主屏安装状态),一律特性检测不嗅探 UA;硬能力(相机/secure context/WASM)缺失 → 阻断页含出路说明;OPFS 缺失 → 放行但 F2 降级、提示常显;未装主屏 → 可关闭的安装引导。

### Epic I — MCP(Agent 访问)

> MCP 工具面(与手机端 REST 共用 service 层,US-G2):读——`list_documents`(日期/标签/名称过滤)、`get_document`(元数据 + 页列表)、`get_file`(original/scan/outfit);组织——`rename_document`、`set_tags`、`reorder_pages`、`list_tags`。输出契约 = 文件 + 元数据,不含 Outfit 组装——agent 需要的 Outfit 由 agent 自行组装(ADR-0005)。

**US-I1 读:列出与检索** · P0 · [ADR-005]
作为 Agent,我想列出/按标签、日期检索 Scan,以便回答"上周的板书扫了吗"。
AC: list/filter 工具;OCR 字段无值返回空不报错。

**US-I2 读:获取内容** · P0 · [ADR-005]
作为 Agent,我想获取 Original/Outfit 文件与 OCR 文本,以便做摘要和知识管理。
AC: 文件可下载或读路径直取(ADR-002 允许裸读)。

**US-I3 组织:重命名/打标签/页组织** · P0 · [ADR-005]
作为 Agent,我想替用户整理库,以便人在扫、agent 在归置。
AC: 与手机端走同一 service 层,改完手机端可见。

### Epic K — OCR(占位,不进 MVP)

**US-K1 OCR 字段与接入点** · P2 · [ADR-005]
SQLite 中 OCR 字段占位(nullable),MCP 读空不报错;后续 PaddleOCR 服务跑批回填(中文板书友好)。
AC: 本 epic MVP 仅落字段 + 接口语义;跑批管线另行立项。

## 4. 明确不做(Out of Scope)

| 项 | 来源 | 理由 |
|---|---|---|
| WebDAV / 云同步 | OSS-DS | 自有服务器即归档真相,无双向同步问题 |
| 本地备份 zip / 恢复 | OSS-DS | 服务器数据 + 文件夹裸读已可备份 |
| 回收站 | OSS-DS | 单用户,误删恢复成本 < 回收站复杂度 |
| QR/条码扫描 | OSS-DS | 超出文档扫描域 |
| 注释/标注 | Lens | 后处理工具,依赖外部 app 更合适 |
| OCR 内建(Tesseract) | OSS-DS | ADR-005:PaddleOCR 后续独立服务 |
| 自动快门 | OSS-DS | 见 US-A6 |
| 多用户/账号系统 | — | ADR-004 单 token |
| 原生 iOS/Android app | OSS-DS | PWA 路线已由 ADR-001/004 锁定 |
| 服务端图像处理管线(reprocess/assemble,原 Epic J)| 自研 | 处理发生在有人的那一端(手机/桌面浏览器/agent 运行时),服务端不碰像素(2026-08-20) |
| agent 触发 reprocess/assemble(原 US-I4/I5)| 自研 | 同 Epic J(2026-08-20) |
