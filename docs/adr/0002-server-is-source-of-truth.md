# 云服务器是唯一数据真相，手机只是缓存与队列

MCP 数据开放接入是本项目的核心诉求之一，agent 读写的对象必须是一个稳定、集中、可检索的位置。决定：aliyun 服务器上的存储是唯一权威——文件按 `YYYY/MM/` 落盘（Original + Outfit），元数据（标签、页序、OCR 占位、来源）存 SQLite。手机端 OPFS 只存会话数据和待上传队列，断网时扫描照常，有网后后台补传，不承担长期存储职责。

考虑过的替代方案：
- 手机 OPFS 为主、同步到服务端：引入双向同步冲突问题，单用户自用场景不值得。

## Consequences

- 手机端"历史"视图是从服务端拉取的列表，本地无档。
- 待上传队列的可靠性要求不高（丢队列 = 重扫），不做持久化重试。
- MCP 读接口直接查 SQLite + 裸读文件夹，任何 agent 工具不经 server 也可读文件。
